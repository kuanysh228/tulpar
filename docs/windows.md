# Windows (.exe)

```bash
tulpar build программа.tlp -o программа.exe     # или: --target windows
tulpar run   программа.tlp --target windows      # соберёт .exe и запустит через wine
```

Компилятор кросс-компилирует из Linux. Никаких дополнительных инструментов (mingw, MSVC, lld) не нужно: используются те же
`as` и `ld`, а PE-файл (заголовки, секции, таблица импорта) записывает сам компилятор (`compiler/src/pe.rs`).
Итог — обычный консольный `.exe` для Windows 10/11 x64 (проверялось в wine), без зависимостей кроме `kernel32.dll` и,
если используется сеть, `ws2_32.dll` (а для `https://` — `secur32.dll` и `crypt32.dll`, см. [docs/networking.md](networking.md)).

## Сам компилятор как `.exe`

Выше речь про программы на Tulpar. Сам компилятор (`tulpar`) — обычная программа на Rust со `std`, поэтому
собирается в Windows `.exe` не своим PE-писателем, а штатной кросс-компиляцией Rust:

```bash
rustup target add x86_64-pc-windows-gnu    # один раз
sudo pacman -S mingw-w64-gcc               # линковщик для этой цели (Arch; в других дистрибутивах — свой пакет)

cd tulpar
rustup run stable cargo build --release -p tulpar --target x86_64-pc-windows-gnu
# -> target/x86_64-pc-windows-gnu/release/tulpar.exe
```

Для раздачи положите рядом с `tulpar.exe` файлы `libtulpar_rt.a`, `libtulpar_win.a`, `libtulpar_kernel.a`
(из `target/release/`, Linux-сборки — формат `.a` переносимый) — `tulpar.exe` находит их по относительному пути
рядом с собой, как и на Linux.

На самой Windows-машине, где будет запускаться этот `tulpar.exe`, всё равно нужны **`as` и `ld`** (GNU binutils) —
компилятор сам ничего не ассемблирует и не линкует, он всегда зовёт их внешним процессом, независимо от платформы.
Проще всего — через [MSYS2](https://www.msys2.org/): `pacman -S mingw-w64-x86_64-binutils` и добавить его `bin`
в `PATH`. Без этого `tulpar.exe build` будет падать с ошибкой `` `as` іске қосылмады ``.

`tulpar.exe`, собранный так, по умолчанию считает целью Windows (можно явно переключить на `--target linux`,
если на той же Windows-машине почему-то нужен Linux ELF) и запускает собранные программы напрямую, без `wine`.

## Как это устроено

1. Генератор кода выдаёт тот же ассемблер, что и для Linux (внутреннее соглашение о вызовах — System V).
2. `ld` собирает статический ELF по скрипту `winrt/win.ld` (адрес 0x140000000, три сегмента: код, константы, данные) вместе
   с `libtulpar_win.a` — рантаймом для Windows (`winrt/`). Он использует **те же** модули GC, строк, списков и словарей,
   что и Linux-рантайм (общий код `runtime/src`); отличается только слой ОС.
3. `pe.rs` превращает ELF в PE32+: каждый сегмент — секция, точка входа — точка входа PE, добавляется секция `.idata`
   с импортом из `kernel32.dll` (и `ws2_32.dll`). Таблицы импорта лежат в самом рантайме (`tlp_iat_k32`, `tlp_imp_k32`),
   поэтому новую функцию WinAPI достаточно добавить в `winrt/src/win.rs`.
4. Вызовы WinAPI идут через `extern "win64"`; всё остальное — внутреннее соглашение System V, поэтому код программы и
   рантайма не знает о Windows.

## Что поддерживается

| возможность | Windows |
|---|---|
| вывод, `оқы()` | консоль переключается на UTF-8 (CP 65001), `\r\n` на вводе обрабатывается; казахские буквы выводятся |
| `аргтар()` | разбор командной строки по правилам MSVC (кавычки, `\"`), UTF-16 → UTF-8 |
| файлы | `файл_оқы/жаз/қос/бар/жой/ауыстыр`, `қалта_жаса` через `…W`-функции (юникодные имена) |
| сеть | TCP/IPv4 через Winsock (`тыңда`, `қосыл`, `қабылда`, `желі_оқы/жаз/жап/күту`) |
| ошибки | деление на ноль, `жоқ`, переполнение стека, индекс и т. д. — те же сообщения и трассировка вызовов, код возврата 1 |
| память | сборщик мусора как в Linux (куча до 2 ГБ, фиксируется по мере роста); `қолмен:` блоки работают |
| стек | 1 ГБ виртуальной памяти (задаётся в заголовке PE), рекурсия глубиной миллионы вызовов |
| время/случайные | `уақыт()`, `кездейсоқ()` |

Не поддерживается: режим ядра (`tulpar os`) и `сыртқы`-функции остаются как есть; графика, GUI-подсистема (всегда консольное
приложение), 32-битные Windows, ARM64.

## Ограничения

* Компилятор работает только на Linux x86-64; запуск полученных `.exe` в Linux — через `wine`.
* Куча ограничена 2 ГБ (константа `GC_HEAP_MAX` в `winrt/src/sys.rs`).
* Приложение не подписано: SmartScreen и антивирусы могут показывать предупреждения для неподписанных `.exe`.
