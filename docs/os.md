# Операционные системы на Tulpar

Tulpar умеет компилировать программу не в Linux-процесс, а в **ядро для голого x86-64 железа**: Multiboot-образ, который грузится
через GRUB, `qemu -kernel` или с ISO/USB. Весь язык работает в ядре как обычно: строки, списки, словари, классы, f-строки,
сборщик мусора, трассировка ошибок. Дополнительно есть встроенные функции для железа: порты ввода-вывода, MMIO, регистры CPU,
прерывания.

```bash
cargo build --release                       # компилятор + оба рантайма (libtulpar_rt.a, libtulpar_kernel.a)

tulpar os run   examples/os/hello.tlp       # собрать и запустить в QEMU (вывод в терминал через COM1)
tulpar os run   examples/os/shell.tlp --gui # то же, но с окном QEMU (VGA-текст) и клавиатурой PS/2
tulpar os build examples/os/hello.tlp -o hello.elf   # Multiboot-ядро (ELF32-обёртка над 64-битным кодом)
tulpar os iso   examples/os/hello.tlp -o hello.iso   # ISO для GRUB (VirtualBox, USB, реальное железо)
```

Нужны: `as`, `ld`, `objcopy` (binutils), для `run` — `qemu-system-x86_64`, для `iso` — `grub-mkrescue` и `xorriso`.

`шығу(код)` завершает работу: QEMU закрывается, а `tulpar os run` возвращает этот код как свой код возврата.

## Что делает рантайм ядра (`kernel/`)

Загрузка (Multiboot 1) → защищённый режим → long mode, страничная память без участия пользователя:

| что | как |
|---|---|
| память | первые 4 ГБ отображены 1:1 (страницы по 2 МБ, область выше 3 ГБ без кэша); **страница 0 не отображена**, поэтому `жоқ` (null) ловится как ошибка |
| SSE | включён (`CR0.EM=0`, `CR4.OSFXSR`), `нақты` работают |
| GDT/TSS/IDT | настроены; ошибки CPU печатаются по-казахски со стеком вызовов и завершают ядро |
| PIC | IRQ 0–15 перенесены на векторы 32–47 и **замаскированы** (размаскируйте нужные через порт `0x21`/`0xA1`) |
| куча | всё свободное ОЗУ после ядра (по Multiboot; до 3 ГБ) отдано сборщику мусора |
| консоль | `жаз`/`көрсет` пишут в COM1 (115200 8N1) и на VGA-текст (80×25, прокрутка; не-ASCII на VGA показывается как `?`, в COM1 идёт UTF-8) |
| ввод | `оқы()` читает строку из COM1 или PS/2 клавиатуры (US-раскладка), с эхом и Backspace; Ctrl-D на пустой строке = конец файла |
| время | `уақыт()` — секунды с загрузки (TSC, калибровка по PIT) |
| ошибки | деление на ноль, `жоқ`, индекс, `қате(...)`, переполнение стека (у стека 1 МБ и страница-ограничитель) и т. д. — сообщение + стек вызовов + выход с кодом 1 |

Недоступны (вызов даёт ошибку времени выполнения): файлы, сеть, `аргтар()`. Драйвер диска или сетевой карты пишете сами, в том числе
на Tulpar.

## Встроенные функции для железа

Работают **только** в режиме `tulpar os …` и **только внутри блока `қолмен:`** (как и указатели).

**Указатели и адреса** (доступны и в обычном режиме):

| функция | значение |
|---|---|
| `мекен(T, адрес)` | `*T` по числовому адресу, например `мекен(байт, 0xB8000)`; `*байт` — 1 байт на элемент, остальные типы — 8 байт |
| `мекенжай(p)` | числовой адрес указателя |

**Порты ввода-вывода:** `порт_оқы8/16/32(порт)`, `порт_жаз8/16/32(порт, значение)`.

**Память (volatile):** `оқы8/16/32/64(адрес)`, `жаз8/16/32/64(адрес, значение)` — для MMIO и структур с нестандартной шириной
полей. Адрес — число или указатель. Обычные `p[i]` по `*байт` и `*бүтін` тоже работают. `жад_көшір(куда, откуда, n)`,
`жад_толтыр(куда, байт, n)` — memcpy/memset.

**Процессор:**

| функция | значение |
|---|---|
| `тоқтат()` | `hlt` (спит до следующего прерывания) |
| `үзіліс_қос()` / `үзіліс_өшір()` | `sti` / `cli` |
| `cr_оқы(n)` / `cr_жаз(n, v)` | CR0, CR2, CR3, CR4 (запись: CR0, CR3, CR4) |
| `msr_оқы(n)` / `msr_жаз(n, v)` | `rdmsr` / `wrmsr` |
| `тактілер()` | `rdtsc` |
| `cpuid(лист, рег)` | `рег`: 0 eax, 1 ebx, 2 ecx, 3 edx |
| `invlpg(адрес)` | сброс записи TLB |
| `жүктеу_ақпараты()` | адрес структуры Multiboot Information (карта памяти, модули…) |
| `пернетақта_оқы()` | неблокирующее чтение символа из PS/2 или COM1, `0` если ничего нет |

**Прерывания:** `үзіліс_орнату(вектор, функция)`. Функция — обычная функция Tulpar с двумя параметрами
`(нөмір: бүтін, код: бүтін)` (номер вектора и код ошибки CPU, 0 если его нет). Для векторов 32–47 (IRQ) сигнал EOI в PIC
отправляется автоматически после возврата. Обработчик исполняется с выключенными прерываниями, на стеке прерванного кода
(ниже red zone), состояние SSE/FPU сохраняется — можно вычислять, читать и писать порты, менять `глобал`-переменные,
писать в `қолмен:`-буферы. **Не выделяйте память в обработчике** (строки, списки, f-строки, `жаз(f"…")`): аллокатор не
реентерабелен, и если прерывание пришло в момент, когда основной код был внутри аллокатора, куча будет повреждена.

```python
тиктер = 0

анықта таймер(нөмір: бүтін, код: бүтін):
    глобал тиктер
    тиктер += 1

қолмен:
    порт_жаз8(0x43, 0x36)                      # PIT, канал 0, 100 Гц
    порт_жаз8(0x40, 11932 % 256)
    порт_жаз8(0x40, 11932 // 256)
    үзіліс_орнату(32, таймер)                  # IRQ0 = вектор 32
    порт_жаз8(0x21, порт_оқы8(0x21) & 0xFE)    # размаскировать IRQ0 в PIC
    үзіліс_қос()
    әзірше тиктер < 100:
        тоқтат()
```

## Примеры

| файл | что показывает |
|---|---|
| `examples/os/hello.tlp` | минимальное ядро: `жаз`, f-строки, `жад()` |
| `examples/os/vga.tlp` | прямая запись в видеопамять `0xB8000` через `мекен(байт, …)` с цветом |
| `examples/os/timer.tlp` | таймер PIT и обработчик IRQ0 на Tulpar |
| `examples/os/shell.tlp` | интерактивная оболочка: ввод строк, команды, `cpuid`, история в списке, GC |

## Как это устроено

* `tulpar os …` включает режим ядра в проверке типов (разрешает `порт_*`, `cr_*` и т. д.) и просит кодогенератор не писать
  `_start` (вместо него в `.data` лежит таблица `tlp_module_desc` с глобальными переменными, таблицей классов и таблицей строк
  для трассировки).
* Результат линкуется с `libtulpar_kernel.a` скриптом `kernel/kernel.ld` (ядро по адресу 1 МБ) и оборачивается в ELF32
  (`objcopy`), потому что `qemu -kernel` понимает только 32-битный ELF. GRUB принимает тот же файл.
* `kernel/` использует **те же** модули `gc`, `str`, `list`, `dict`, `fmt`, `math`, что и обычный рантайм (подключены через
  `#[path]`); заменён только ОС-слой (`kernel/src/sys.rs`): консоль, память из `os_map`, ввод, выход.
* Вход (`kernel/src/lib.rs`): 32-битная заглушка Multiboot строит таблицы страниц, включает long mode и вызывает
  `tlp_kernel_start` (Rust), который настраивает GDT/IDT/PIC, кучу и запускает `tlp_main`.
* Прерывания: заглушки векторов (`kernel/src/arch.rs`) получают управление на отдельном стеке IST1, переносят кадр на стек
  прерванного кода и вызывают диспетчер; двойная ошибка (#DF) идёт на отдельный IST2, поэтому переполнение стека
  выводит сообщение, а не приводит к triple fault.

## Ограничения и что делать дальше

* Только x86-64, один процессор, без SMP; ядро всегда в кольце 0. Для пользовательского режима, системных вызовов и
  собственной страничной памяти нужно самостоятельно написать таблицы страниц (`cr_жаз(3, …)`), расширенный GDT/TSS и
  `syscall`/`int`; встроенных функций для `lgdt`/`lidt`/`iretq` пока нет (рантайм владеет GDT и IDT).
* Куча предполагает, что свежее ОЗУ заполнено нулями (QEMU и GRUB это обеспечивают; на реальном железе после холодного
  старта обычно тоже, но не гарантируется).
* GC консервативный, однопоточный, не реентерабельный (см. выше про обработчики прерываний).
* Образ для GRUB собирается только для BIOS (Multiboot 1); для UEFI нужен загрузчик с поддержкой Multiboot2 — не реализовано.
* Кириллица и казахские буквы на VGA-тексте не показываются (аппаратный шрифт CP437); в COM1/терминале всё в UTF-8.
