# Сеть: DNS, HTTP/HTTPS-клиент

## Что нового

* **DNS.** `қосыл(host, port)` теперь принимает настоящее доменное имя, не только IPv4-литерал или `localhost`.
  На Linux это собственный UDP-клиент (`/etc/resolv.conf`, запрос A-записи), на Windows — системный `GetAddrInfoW`.
  Резолвится только IPv4 (A-запись); при неудаче `қосыл` возвращает `-1`, как и раньше при любой ошибке соединения.

* **Удобный HTTP/HTTPS-клиент** — чтобы не собирать запрос вручную через `желі_*`:

  ```python
  дене = тор_алу("https://example.com/")
  ```

  `тор_алу(url)` — GET-запрос. Сам идёт по редиректам (до 10), возвращает тело ответа как `мәтін`.
  Останавливает программу с ошибкой при сбое сети/DNS или если итоговый код ответа `>= 400`.

  ```python
  тақырыптар: сөздік[мәтін, мәтін] = {"X-Сынақ": "1"}
  код, тақырыптар_жауап, дене = тор_сұрау("https://httpbin.org/post", "POST", "a=b", тақырыптар)
  ```

  `тор_сұрау(url, әдіс="GET", дене="", тақырыптар={})` — один запрос без редиректов. Возвращает кортеж
  `(код: бүтін, тақырыптар: сөздік[мәтін, мәтін], дене: мәтін)`. Ключи заголовков ответа приходят в нижнем регистре.
  `Host`, `Content-Length` и `Connection` в своих заголовках передавать не нужно — клиент выставляет их сам
  (всегда `Connection: close`, одно соединение на запрос). Понимает `Transfer-Encoding: chunked` на входе.

## HTTPS: что именно происходит и где работает

HTTPS сделан принципиально без единой строчки собственной криптографии — расшифровка, проверка сертификата
и TLS-хендшейк целиком выполняются операционной системой:

| платформа | что используется | статус |
|---|---|---|
| Windows (`--target windows`) | **Schannel** (`secur32.dll`) — тот же TLS-стек, что у Edge и остальных Windows-программ | работает |
| Linux (обычная сборка) | — | `тор_алу`/`тор_сұрау` с `https://` останавливают программу с понятным сообщением |

На Windows проверка сертификата выполняется **дважды**, независимо друг от друга:

1. Автоматическая проверка самого Schannel во время хендшейка (включена по умолчанию — явно не отключается).
2. Отдельный, самостоятельный вызов `crypt32.dll` (`CertGetCertificateChain` + `CertVerifyCertificateChainPolicy`)
   после хендшейка: проверяет цепочку доверия до системного хранилища корневых сертификатов и совпадение
   имени хоста с сертификатом. Это сделано специально, не только для надёжности: пока это разрабатывалось,
   тестовая среда (Wine) оказалась первым случаем, где стоило не доверять слепо встроенной проверке Schannel
   на глаз — вторая проверка поймала бы это сама, если бы первая подвела.

Проверено на живых сайтах под Wine: `example.com`, `httpbin.org` (валидные сертификаты) — соединение проходит;
`self-signed.badssl.com`, `expired.badssl.com`, `wrong.host.badssl.com` — все три корректно **отклоняются**
с ошибкой `TLS: сервердің сертификаты сенімсіз немесе хост атауына сәйкес келмейді`.
На настоящей Windows (не Wine) поведение не проверялось — если увидите разницу, это повод завести issue.

Почему не на Linux: на Linux нет готового, проверенного TLS без системной библиотеки вроде OpenSSL, а сам
рантайм написан без единой внешней зависимости (`no_std`, без libc, без крейтов). Писать TLS-хендшейк и
проверку сертификатов руками — вручную реализовывать криптографию и X.509 — тот случай, где маленькая ошибка
(например, неполная проверка цепочки) не баг, а тихая дырка: программа будет выглядеть защищённой, не будучи
защищённой. Делать это наспех того не стоит.

## Устройство (для желающих читать код)

* `runtime/src/dns.rs` — DNS-клиент для Linux: без побочных библиотек, те же сырые syscalls, что и весь рантайм.
* `runtime/src/http.rs` — HTTP-клиент для Linux (`http://` только; `https://` сразу завершает с ошибкой).
* `winrt/src/http.rs` — HTTP/HTTPS-клиент для Windows; TLS вынесен в `winrt/src/tls.rs`.
* `winrt/src/tls.rs` — драйвер Schannel: цикл `InitializeSecurityContextW`, затем `EncryptMessage`/`DecryptMessage`
  на поток приложения. Сама библиотека `schannel.dll` делает всю криптографию.
* `winrt/src/win.rs` — типизированные обёртки над WinAPI (`secur32.dll`, `crypt32.dll`, `ws2_32.dll`), включая
  независимую проверку сертификата через `crypt32`.
* `compiler/src/pe.rs` — писатель PE: каждая используемая DLL (kernel32 обязательно, ws2_32/secur32/crypt32
  по необходимости) получает свою запись в таблице импорта.

## Ограничения

* Только IPv4 — ни в DNS, ни в TCP-соединениях IPv6 нет (как и раньше).
* HTTPS — только Windows-сборки.
* `тор_сұрау`/`тор_алу` не переиспользуют соединение (keep-alive): каждый запрос — новое TCP (и, для HTTPS,
  TLS) соединение. Для одного запроса это не важно; для множества запросов к одному серверу будет медленнее,
  чем могло бы быть.
* DNS резолвит только A-записи, без кэширования между вызовами.
